## 1. 接入与部署

### US-1.1 确认企业具备接入条件 `P1`
**作为**企业管理员，**我想要**在投入实施前知道我的腾讯会议账号能否调用 API，**以便**不在不可能成立的方案上浪费时间。

- 明确列出账号版本要求：免费版与专业版**不支持调用任何 REST API**
- 提供可执行的自检方式，部署前即可验证凭证与权限
- 版本不满足时给出明确结论，而非模糊报错

> 依据 spec §3.4。这是阻断性前提，须最先确认。

### US-1.2 完成网关部署与凭证配置 `P1`
**作为**企业管理员，**我想要**按文档在阿里云部署网关并填入腾讯会议凭证，**以便**建立企业统一的导出通道。

- SecretKey 等凭证不以明文存在于配置文件或数据库
- 配置错误时启动阶段即报出具体原因（哪个凭证、哪项权限）
- 部署产物为容器镜像，不要求手工安装运行时依赖

### US-1.3 建立 STS-Token 自动续期 `P1`
**作为**企业管理员，**我想要**配置一次事件订阅后 Token 自动维持有效，**以便**不必人工干预凭证轮换。

- Token 在过期前自动续期，续期期间服务不中断
- 回调超时未收到 Token 时告警，并明确指出受影响的能力范围（AI 纪要不可用，录制与逐字稿不受影响）
- Webhook 端点拒绝未通过验签的请求

> 依据 spec §5.3。回调为异步下发，因此按剩余有效期 1/3 提前触发，新旧 Token 并存。

### US-1.4 确认身份映射可用 `P1`
**作为**企业管理员，**我想要**在上线前验证员工的企微身份能正确对应到腾讯会议账号，**以便**策略能真正按人生效。

- 支持 `direct` / `email` / `table` 三种映射策略，可配置
- 提供工具用真实账号实测映射结果
- 映射不通时给出的是配置错误提示，而非把用户当作「无权限」

> 依据 spec §5.4.4。**这是阻断性前提**：若三种策略都无法可靠对应，US-2.1 不成立。

## 2. 数据管控

### US-2.1 限定可导出的数据范围 `P1`
**作为**企业管理员，**我想要**规定谁可以导出哪些会议的哪类资产，**以便**满足公司的数据管理要求。

- 规则可按人员、部门、会议属性、资产类型组合
- 未配置任何规则时默认拒绝
- 规则变更即时生效，无需重启
- 规则可被管理员读懂并审计（仅等值、集合包含、时间区间三种操作，无嵌套逻辑）

> 依据 spec §5.5。默认 deny 意味着**装好后不配规则是不能用的**，见 Q2。

### US-2.2 管控无法被绕过 `P1`
**作为**企业管理员，**我想要**确信员工无法绕过策略直接取数，**以便**管控是真实有效的而非表面功夫。

- 客户端不持有腾讯会议凭证
- 构造他人的资产 ID 直接请求下载地址会被拒绝，而不仅是列表里看不到
- 收紧策略后，持有未过期令牌的用户下一次请求即被拒（令牌内不缓存策略结果）
- 拒绝行为留下审计记录

> 依据 spec §4.1 与 §5.5。三个执行点中，只有「换下载地址」是真正的授权检查。

### US-2.3 签发与吊销自动化凭证 `P1`
**作为**企业管理员，**我想要**为定时归档任务签发独立凭证并能随时吊销，**以便**自动化任务与个人身份解耦。

- 服务账号凭证可设置绝对过期时间
- 吊销后即时失效
- 服务账号同样受策略约束，不享有绕过特权
- 密钥明文仅在签发时展示一次

## 3. 登录与身份

### US-3.1 扫码登录 `P1` `P4`
**作为**业务用户，**我想要**用企业微信扫码登录，**以便**不必记额外的账号密码。

- 扫码后进入应用，身份与企微账号一致
- 身份无法映射到腾讯会议账号时，提示「账号未开通」而非「无权限」
- 授权页面被他人诱导扫码时无法劫持会话（`state` 一次性校验）

### US-3.2 在命令行完成登录 `P2`
**作为**业务用户，**我想要**在没有浏览器的终端（含远程服务器）上完成登录，**以便**在服务器上跑归档任务时也能用自己的身份。

- 终端内直接渲染二维码，无需把链接复制到别处
- 同时打印可手工访问的链接与验证码，供二维码无法显示时使用
- 授权完成后命令自动继续，无需手工粘贴任何凭证
- 超时未授权时明确提示并可重新发起

> 依据 spec §5.4.1。CLI 无法承接 OAuth 重定向回调，因此桌面端与 CLI 统一采用设备授权流程（RFC 8628）。

### US-3.3 保持登录与主动登出 `P1` `P2` `P4`
**作为**业务用户，**我想要**登录状态能保持一段时间，也能在需要时主动退出，**以便**日常使用不必反复扫码，换机器时又能确保凭证失效。

- 登录状态保持 7 天，期间自动续期无感
- 主动登出后旧凭证立即失效
- 凭证被窃取并重放时，系统能察觉并吊销该用户全部会话

> 依据 spec §5.4.5。刷新即轮换 + 重放检测。

## 4. 查找与导出

### US-4.1 浏览一段时间内的会议 `P1` `P2`
**作为**业务用户，**我想要**指定一段时间并看到我有权导出的会议，**以便**挑选需要归档的内容。

- 时间范围超过 31 天时由工具自动切分，用户无感
- 列表只包含策略允许的会议
- 显示主题、时间、主持人，足以辨认

### US-4.2 导出指定的某一场会议 `P1` `P2`
**作为**业务用户，**我想要**凭手上的会议号找到并导出那一场会议，**以便**不必为了一场会而导出整个月。

- 支持用会议号（9 位，邀请函上的号码）查找，不要求用户知道内部会议 ID
- 一个会议号命中多场会议时，列出全部候选供选择，不擅自择一
- 会议不在默认时间范围（最近 31 天）内时，提示「可扩大时间范围」，而非笼统的「未找到」
- 与批量归档混用时不产生重复下载

> 依据 spec §5.2 与 A.8。平台侧 `start_time`/`end_time` 为必填，
> 不存在「仅凭会议 ID 查询」的路径，故有默认窗口这一设计。

### US-4.3 取回一场会议的全部资产 `P2`
**作为**业务用户，**我想要**把一场会议的录制、音频、逐字稿、AI 纪要一次性下载到本地，**以便**完整保存这场会议。

- 八类资产按可得性尽量取全
- 每类资产的缺失原因可查（未开放下载 / 尚未生成 / 策略拒绝）
- 文件按会议组织成目录，目录名可读
- 文件扩展名与实际格式一致（平台可能返回 txt / pdf / docx / htm）

### US-4.4 只导出需要的资产类型 `P2`
**作为**业务用户，**我想要**指定只下载纪要而不下载几 GB 的视频，**以便**快速拿到我真正需要的内容。

- 可按资产类型筛选导出
- 未选中的类型不产生下载任务，也不占用配额
- 事后可补充导出其余类型，已导出的不重复

### US-4.5 中断后继续而非重来 `P2`
**作为**业务用户，**我想要**在网络中断或关机后重新运行时从断点继续，**以便**不必为一个几 GB 的录制重下一遍。

- 重新运行自动续传，无需专门的恢复命令
- 已完成的资产不重复下载
- 下载链接过期不导致从头开始（链接仅 5 分钟有效，大文件必然中途过期）

### US-4.6 知道当前进度与失败原因 `P2`
**作为**业务用户，**我想要**看到每个任务的状态和失败原因，**以便**判断是等待、重试还是放弃。

- 可查询各状态的数量与失败明细
- 失败原因是可理解的描述，而非原始错误码
- 可一键重试失败项

### US-4.7 等待延迟生成的 AI 纪要 `P2`
**作为**业务用户，**我想要**在录制已下载但纪要尚未生成时，工具能在纪要生成后自动补齐，**以便**不必反复手工检查。

- 录制就绪即下载，不被未生成的纪要阻塞
- 后续运行时自动补齐已生成的纪要
- 确认不会生成的（未开放下载）立即标记，不无谓等待

> 依据 spec A.4。`allow_download=false` 时可即时判定，
> 超时上限（视频 6 小时 / 纪要类 48 小时）仅作安全网。产品表达见 Q5。

## 5. 无人值守归档

### US-5.1 定时自动归档 `P2`
**作为**归档运维，**我想要**配置定时任务持续归档新产生的会议，**以便**建立长期的自动化归档机制。

- 命令可重复执行且幂等，重复运行不产生重复数据
- 使用服务账号凭证，无需人工扫码
- 单次运行失败不影响后续运行的正确性
- 非交互环境下遇到歧义（如会议号多结果）直接失败并给出候选，不自动择一

### US-5.2 导出到企业存储 `P3`
**作为**归档运维，**我想要**把资产直接落到阿里云 OSS 或公司 NAS，**以便**归档数据进入企业既有的存储与备份体系。

- 存储目标可配置，切换目标不需要迁移已有记录
- 大文件写入支持中断续传
- 写入失败有明确错误，不产生残缺文件

## 6. 审计与合规

### US-6.1 核查数据导出记录 `P1`
**作为**合规审计，**我想要**查到谁在何时导出了哪场会议的哪类资产，**以便**在需要时说明数据流向。

- 每次签发下载地址均有记录
- 记录包含操作者、时间、会议、资产类型、策略判定结果
- 登录成功与失败同样记录
- 记录不可被普通用户修改或删除

### US-6.2 归档结果可脱离系统理解 `P2`
**作为**合规审计，**我想要**在存储上直接看懂归档目录的内容与完整性，**以便**不依赖导出工具本身也能核查。

- 每个会议目录包含元数据文件与资产清单
- 清单标明每项资产的原始 ID、大小、校验值
- 确认缺失的资产在清单中显式标注原因（「确认缺失」与「不知有无」是两种状态）

## 7. 桌面端体验

### US-7.1 无需安装依赖即可使用 `P4`
**作为**业务用户，**我想要**下载安装包双击即用，**以便**不必安装运行时或命令行工具。

- macOS 与 Windows 各提供安装包
- 不要求用户安装 Bun、Node 或其他依赖
- 安装包经过签名，系统不拦截

### US-7.2 可视化查看与操作任务 `P4`
**作为**业务用户，**我想要**在界面上看到会议列表和下载进度并控制任务，**以便**不必使用命令行。

- 显示每个任务的进度与状态
- 可暂停、继续、重试
- 桌面端与 CLI 使用同一份数据，交替使用不冲突

## 8. 需求验证问题

设计文档仍未回答的问题，需要你判断。**Q1 已从「无方案」推进到「有方案待确认事实」，其余不变。**

### Q1. 企微身份与腾讯会议身份如何对应？（阻断性 · 已有方案，待确认事实）

策略判定依据是会议的 `host_user_id`（**腾讯会议 userid**），而登录身份来自**企业微信**，两套 ID 不必然相同。

spec §5.4.4 已补 `IdentityMapper`，提供三种可配置策略：

| 策略 | 前提 |
| --- | --- |
| `direct` | 企业通过企微对接腾讯会议 SSO，两侧 userid 同源 |
| `email` | 两侧均有可靠且唯一的邮箱 |
| `table` | 管理员维护显式映射表 |

**需要你确认的是事实而非方案**：贵司的腾讯会议账号体系是怎么建立的——企微 SSO 打通的，还是独立创建的用户？

必须取真实账号实测，不能凭假设。已列入 spec §6 阻断性检查项，对应 US-1.4。

### Q2. 默认的组织策略是什么？（影响产品形态）

spec 定义了策略**机制**，但没定义**默认配什么规则**。这是业务问题：

- 员工能导出自己**主持**的会议吗？
- 能导出自己**参与但非主持**的会议吗？
- 部门负责人能导出本部门所有会议吗？
- 还是一律只有管理员能导，员工需申请？

**这个答案决定桌面端的定位**。§3、§4、§7 的故事都是按「员工能自助导出」写的；如果实际是「只有管理员能导」，那 US-7.1 的传播性诉求不成立，桌面端应重新定位为管理员工具。

### Q3. 导出之后的文件谁能访问？

spec 管住了「谁能**导出**」，没管「导出后谁能**看**」。资产落到 NAS 或 OSS 后，访问控制由文件系统或对象存储决定，与策略引擎无关。

可能的结果：策略禁止 A 导出 B 部门的会议，但 A 能直接打开 NAS 上别人导出的同一批文件——**管控在最后一步失效**。

需确认：导出目标的权限体系由谁管？是否需要按部门写入不同目录并施加不同权限？

### Q4. 子项目 1 单独交付时没有可演示的用户价值

网关交付后，管理员完成部署和配置——然后什么也做不了，因为没有客户端。上面所有 `P2`/`P4` 故事都还不可用。

需确认验收方式：

- 接受「以 API 契约 + 自动化测试验收」，还是
- 需要一个最小验证客户端（哪怕一组 curl 脚本）演示端到端跑通

我建议后者，成本很小但能真正验证网关可用。

### Q5. 48 小时等待期在产品上如何表达？

AI 纪要可能需等待数十小时，期间会议处于「录制已下载、纪要待生成」的部分完成状态。

- 显示为「已完成（部分）」还是「进行中」？
- 用户会不会误以为工具卡住？
- 是否需要在导出结束时明确告知「纪要将在生成后自动补齐」？

### Q6. 会议范围的默认口径未定

网关用固定 operator 账号（企业管理员）调用，理论上能看到全企业录制。那么客户端不传过滤条件时：

- 返回全企业会议，还是仅与该用户相关的会议？
- 「相关」的定义是什么（主持 / 参与 / 本部门）？

与 Q2 相关，但更具体地影响 US-4.1 的默认体验。
