## 1. 产品模型

一句话：**把腾讯会议的录制与纪要收进来，归档进 NAS，在本地留一个窗口期，
期间按规则和授权让外部程序取走；窗口期一到删本地文件，只留记录和 NAS 路径。**

### 1.1 四个阶段

```
腾讯会议
   │
   │ ① 拉取        由「拉取规则」决定拉哪些会议、拉哪几类资产
   ▼
本系统本地
   │
   │ ② 归档 NAS    由「归档规则」决定进 NAS 的哪个目录
   ▼
NAS（长期唯一存放地）
   │
   │ ③ 本地保留 30 天    自**归档成功**日起算，不是自会议日起算
   │    这期间外部程序可以取
   ▼
   ④ 到期            删本地文件，保留数据库记录 + NAS 路径
```

登录页底部那条点线就是这四个阶段，不是装饰。

### 1.2 NAS 是主存储，不是备份

这是整套系统最容易被误解的一点，也是所有告警等级的来源：

> **没有归档成功的会议，本地保留期一到就彻底没有了。**

腾讯会议侧的录制有自己的留存策略，不能假定它一直在。所以：

- **归档失败是本系统最高级别的告警**，红色，且在会议列表的分诊条里单列一格
- NAS 断连时，控制台**提供「暂停到期清理」的应急开关**（见 §7.2）——那是唯一能
  阻止不可逆损失的动作，所以它必须出现在告警条本身上，而不是藏在设置里

### 1.3 外部程序真能取到 = 三个「与」

```
有授权（这场会议授权给了这个程序）
  且  在保留期内（本地文件还没被删）
  且  规则允许采集（权限规则栈判定 allow）
```

三个条件缺一不可，且**分别由不同的人、在不同的页面维护**。界面必须随时能回答
「为什么这场会议这个程序取不到」——所以每场会议的详情里都有逐阶段的**判定理由**
（`why.fetch` / `why.archive` / `why.allow`）。

### 1.4 数据出企业边界的唯一闸门

**采集权限规则是数据离开企业边界的唯一闸门。** 任何新增的出境路径（例如把会议
内容送给大模型做问答）都必须走同一道闸门，不能从别的页面另开一个口子。

原型的内容预览页右下角为「向这场会议提问」留了位置但**刻意没有实现**，理由写在
界面上：那是一条新的出境路径，真要接就当一个采集程序来管——走接入向导拿凭据、
受规则和授权约束、每次问答记一条审计。

## 2. 角色与权限

| 角色 | 能做什么 | 原型状态 |
| --- | --- | --- |
| **数据管理员** | 全部：改规则、改授权、延长保留、手动触发任务、看内容 | ✅ 已实现 |
| **只读角色** | 只能看，不能改任何状态 | ❌ **未设计**，见 §11 |

M2 已确认「**仅管理员可导**」，所以控制台不面向全员。当前用户菜单里写着
「数据管理员 · 可改规则与授权」，但**系统里只有这一个角色**，只读角色是缺口。

**管理员查看会议内容会留痕。** 尤其是被规则禁止采集的会议——管理员仍然能看
（他要判断这条规则拦对了没有），但顶部挂琥珀警示条，且这次查看进审计日志。

## 4. 逐页说明

### 4.1 登录

![登录](screens/01-登录.webp)

账号 + 密码 + 「记住此设备 30 天」。仅限内部管理员，无自助注册、无找回密码
（文案明说「忘记密码请联系系统管理员开通」）。

**这是独立于企微的账号体系**（D1，2026-08-23），不是待定项——理由见 §10。

- 报错行是**表单级**的（"账号或密码错误" 故意不说是哪个字段错了），常驻占位，
  避免出错时表单跳一行
- 底部四阶段点线是产品模型的可视化，不是进度条

### 4.2 会议记录（主页面）

![会议记录](screens/02-会议记录.webp)

**分诊条**（五格，每格可点即筛选）——把「现在有什么需要处理」压成一行：

| 格 | 含义 | 颜色 |
| --- | --- | --- |
| 归档失败 | 到期会永久丢失 | 红 |
| 7 天内到期 | 过期后须去 NAS 取 | 琥珀 |
| 待授权 | 准许采集但没给程序 | 蓝 |
| 处理中 | 拉取或归档进行中 | 中性 |
| 仅存 NAS | 本地已清理 | 中性 |

**表格列**：

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 会议记录 | 标题 + 会议号 + 时间 | 标题是按钮，点进内容预览 |
| 主持人 | | |
| 资产 | `已拿到/应有` | 如 `19` 或 `7/19`（部分失败）或 `0/19` |
| 拉取 · 归档 | 两个圆点 + 连线 | **圆点即开关**，点一下就能重跑该阶段 |
| 本地保留 | 进度条 + 剩余天数 | hover 出现「+30 天」按钮 |
| 已授权给 | 程序 pill，可加可删 | `+ 授权给…` 打开程序选择弹层 |

- **批量**：勾选后底部浮出批量条（授权 / 延长 / 重跑）
- **跨页全选有逃生门**：勾表头只选本页，要选全部得再点一次，且明说总数
- **人工改写优先于所有规则**，改写过的行有标记

### 4.3 会议详情（右侧抽屉）

![会议详情抽屉](screens/03-会议详情抽屉.webp)

四段，对应产品模型的四个阶段，每段带**判定理由**：

1. **拉取** —— 状态 + 是哪条规则决定的 + 八类资产各自的格式数与体积 + 「撤销拉取」
2. **归档到 NAS** —— NAS 路径（可复制）+ 归档时间 + 体积 + 「撤销归档」
3. **本地保留** —— 大号剩余天数 + 归档日/到期日 + 「延长 30 天」
4. **采集授权** —— 已授权程序 + 是哪条权限规则放行/禁止的

底部是**这场会议的操作历史**（谁在什么时候取走了什么）。

### 4.6 自动规则

![自动规则](screens/09-自动规则.webp)

三组规则栈，各管一件事：

| 组 | 决定 | 兜底 |
| --- | --- | --- |
| **一、拉取规则** | 去腾讯会议拉哪些会议、拉哪几类资产 | `skip`（不拉） |
| **二、归档规则** | 往 NAS 的哪个目录归档 | `skip` |
| **三、采集权限规则** | 哪些会议准许被外部程序取走 | **`deny`（默认全部拒绝）** |

第三组的兜底是 deny，前两组是 skip——因为第三组是数据出境闸门，默认必须是关的。

### 4.7 规则编辑器

![规则编辑器](screens/10-规则编辑器-影响预览.webp)

右侧全高面板，比抽屉宽，因为**条件构建器和影响预览必须同屏**。

> 规则的难点从来不是「怎么填」，是「填完之后有多少场会议的状态会变」。

- **条件行**：字段 + 运算符 + 值，连接词在左侧竖排
- **一条规则内只能全用「且」或全用「或」**——这是刻意限制。混用而没有括号，
  读起来通顺，求值顺序却常常和人的直觉不一样。需要混用就拆成两条规则
- **影响预览钉在底部**，不跟正文滚动，三个数：`场命中` / `场新放行` / `场新收紧`
- 有会议**从未对外开放过**却将被这条规则放行时，额外出一条琥珀警告
- 删除按钮默认是安静的，点第一次才变红（二次确认）

点规则行右侧的**命中数**可以看具体是哪几场：

![命中的会议](screens/10b-规则命中的会议.webp)

### 4.8 定时任务

![定时任务](screens/11-定时任务.webp)

四个任务串起整条链路：

| 任务 | 频率 | 干什么 |
| --- | --- | --- |
| 一、拉取新录制 | 每 15 分钟 | 发现新录制并入队 |
| 二、归档到 NAS | 每小时整点 | 写入 NAS 并校验哈希 |
| 三、清理到期文件 | 每天 03:00 | 删本地文件，**记录与 NAS 路径保留** |
| 四、刷新采集清单 | 每 5 分钟 | 重算哪些会议对哪些程序可见 |

- 每个任务带一条**近期运行的 sparkline**，失败的那次是红的
- **失败项不会静默丢弃**，会一直留在下方的「失败项 · 需要处理」表里等重试，
  且明写影响（「未归档，到期会永久丢失」）和已重试次数（`2 / 5`）

### 4.9 归档存储

![归档存储](screens/12-归档存储.webp)

两块：

- **NAS 归档** —— 挂载点、协议、连通状态、最近检测时间、容量占用（本系统 / 其他 / 剩余）、
  已归档 / 归档中 / 归档失败
- **本地保留窗口** —— 保留期内 / 其中已授权 / 7 天内到期 / 本地占用，
  以及三个动作：修改默认保留天数、导出可采集清单、立即清理已到期文件

页面底部那段话是产品模型的复述，必须留着：

> 到期只删本地文件，**数据库记录永久保留**——会议标题、时间、主持人、内容哈希、
> 以及归档到 NAS 的具体目录。所以历史会议在这里依然搜得到，只是要按给出的路径去 NAS 取。

### 4.10 操作审计

![操作审计](screens/13-操作审计.webp)

一行一次访问。**人和程序混在同一条流里**，用左侧色块区分（`prog` 蓝 / `person` 中性 / `sys` 灰）。

字段：时间 · 操作者 · 动作 · 对象（会议标题 + 会议号）· 结果。

- **被拒绝的记录是红的**，且写明拒绝原因（「拒绝 · 本地已到期，请去 NAS 取」）
- 管理员查看规则禁止采集的会议，这里会有一条「规则禁止采集，管理员查看已留痕」
- 支持按操作者 / 类型 / 时间范围筛选

## 5. 规则引擎语义

**这一节需要逐字实现，不能凭直觉。**

### 5.1 求值

```
对某一类规则（fetch / archive / allow）：
  1. 取出该类中 enabled 的全部规则
  2. 按 priority 降序排序
  3. 从上往下找第一条匹配的，用它的 effect，立即停止
  4. 一条都不匹配时用兜底：allow 类 → deny，其余 → skip
```

**第一条命中的说了算**，不做合并、不做叠加。

两条必须写死的细节：

1. **同优先级的平局**：按 `id` 升序，先建的先命中。不按 effect 决定平局——
   「deny 优先」是另一套语义（合并式），与本节的「第一条说了算」互斥，混用会让
   规则列表的顺序不再是判定顺序，管理员就读不出结果了。
2. **与现有实现相反**：`src/policy/engine.ts` 当前按 priority **升序**取第一条，
   且同优先级 deny 优先。阶段 3 的 R1 以本节为准重写，**并且必须写迁移**：
   迁移跑完后拿迁移前的规则集与会议集重算一遍，判定结果逐条比对，不一致的列出来
   交人工确认——不许脚本自行决定。

### 5.2 单条规则的匹配

```
无条件（conds 为空）           → 匹配一切
join === 'or'                  → 任一条件成立即匹配
join === 'and'（默认）         → 全部条件成立才匹配
```

**一条规则内只有一个连接词**，不支持括号与混用。

### 5.3 可用字段与运算符

| 字段 | 运算符 | 值 |
| --- | --- | --- |
| 会议标题 `title` | 包含任一 / 不包含 | 关键词，逗号分隔 |
| 主持人部门 `dept` | 属于 / 不属于 | 部门多选 |
| 主持人 `host` | 是 / 不是 | 人员 |
| 会议时长 `dur` | 大于 / 小于 | 分钟 |
| 录制结束 `age` | 在最近 N 天内 / 早于 N 天 | 天 |
| 归档状态 `arch` | 已写入 NAS / 未归档 | 无值 |

> **`dept` 依赖企微通讯录，网关目前没有这份数据。** 它是归档规则最自然的写法
> （「财务部的会议归到 /nas/meetings-finance/」），所以**不删这个字段**，而是把
> 「接企微通讯录 API + 部门同步」立成阶段 3 的前置任务 R0。
> 在 R0 落地前，规则编辑器里这个字段应当可见但禁用，并写明原因——
> 不要让它看起来能用却静默不匹配。

### 5.4 人工改写

**单场会议的人工改写优先于所有规则。** 改写过的会议在列表里有标记，
且规则的影响预览要把它们排除在「会被改变」之外。

### 5.5 影响预览的计算范围

只在 `命中(旧规则) ∪ 命中(新规则)` 这个集合上算，**不是全部会议**。
把所有会议都列成「受影响」是虚假的规模感。

## 6. 数据模型

### 6.1 会议

```js
{
  id, title, code,            // 会议号 881-123-40
  when, host, dur,            // 8-21 14:00 · 邹研发 · 1:52
  assets, total,              // 已拿到 / 应有
  fetch:   'done' | 'running' | 'blocked' | 'none',
  archive: 'done' | 'running' | 'failed' | 'off' | 'blocked' | 'none',
  allow:   'allow' | 'deny',
  grants:  ['知识库索引器', ...],   // 只有 allow 且在保留期内才有意义
  hand:    [],                      // 被人工改写过的阶段
  keep: { archivedOn, expiresOn, daysLeft, extended, filesGone },
  nas, size,
  why: { fetch: {by, text}, archive: {...}, allow: {...} },  // 逐阶段判定理由
  hist: [[时间, 事件], ...]
}
```

`why.by` 的取值决定理由的呈现样式：`rule`（来自规则）· `hand`（人工改写，琥珀）·
`fail`（失败，红）· `expired` / `wait` / `na`（生命周期原因，优先级高于权限原因）。

### 6.2 八类资产

| key | 名称 | 网关 `asset_type` |
| --- | --- | --- |
| `summary` | AI 纪要 | `ai_minutes` |
| `transcript` | 完整转写 | `meeting_summary` |
| `speaker` | 发言人纪要 | `ai_speaker_minutes` |
| `topic` | 话题纪要 | `ai_topic_minutes` |
| `aitr` | AI 转写 | `ai_meeting_transcripts` |
| `digest` | 会议摘要 | `ai_ds_minutes` |
| `video` | 录像 | `video` |
| `audio` | 音频 | `audio` |

**这一列的权威在代码里，不在本表**：`packages/engine/src/domain/types.ts` 的
`ASSET_KEY_TO_GATEWAY_TYPE` 是唯一事实源，本表只是它的人类可读副本。两处不一致时以代码为准。

左列那套短名（`summary` / `aitr` / `digest`）**只是原型 HTML 内部的显示用键**。
前端工程化（F1）时必须直接采用 `AssetKey`，**不要把这套短名带进代码**——同一批资产
已经有过三套叫法，M3.5 为此吃过一次亏（见 `dev-plan.md` §5 C7）。

同一份录制的多种导出格式（txt / docx / pdf）**共享同一个 `record_file_id`**，
只有 `file_type` 能区分它们——这个坑已经在 `client/src/store/db.ts` 的 schema v2
里踩过并修了，控制台侧的资产计数必须沿用同样的唯一键。

### 6.3 规则

```js
{ id, kind: 'fetch'|'archive'|'allow', pri, enabled,
  join: 'and'|'or', conds: [{ f, op, v }], effect,
  note,          // 说明，会出现在规则列表和每场会议的判定理由里
  author, on }   // 谁在什么时候建的
```

**主体（谁）在三栈里的含义不同**：

| 栈 | 主体 | 说明 |
| --- | --- | --- |
| 拉取 `fetch` | **无** | 系统级行为，不针对任何人 |
| 归档 `archive` | **无** | 同上 |
| 采集权限 `allow` | **采集程序** | 不是人。对应 `service_accounts.id` |

现有 `policy_rules.subject_type` 只认 `user`，需增加 `program` 取值；fetch / archive
两栈的主体列留空，并在引擎里**显式忽略**（不是「恰好匹配不上」）。

### 6.4 采集程序

```js
{ id, name, scope }   // kb-indexer · 知识库索引器 · 'AI 纪要 + 完整转写'
```

## 7. 系统状态与降级

控制台依赖三个外部系统，**它们各自挂掉的后果完全不同**，所以告警等级和给出的
操作也不一样。

| 依赖 | 挂了会怎样 | 等级 |
| --- | --- | --- |
| 腾讯会议接口 | 只影响拉新的。已拉下来的会议、归档、对外采集都不受影响 | 琥珀 |
| **NAS 归档存储** | **最要命**。归档不成功的会议，本地保留期一到就彻底没有了——这是本系统唯一不可逆的损失 | 红 |
| 数据库 | 整个后台读不出数据，但不会丢东西——文件还在，记录还在 | 红 |

### 7.1 腾讯会议不可达

![腾讯会议不可达](screens/15-系统状态-腾讯会议不可达.webp)

### 7.2 NAS 断连

![NAS 断连](screens/14-系统状态-NAS断连.webp)

**故障必须在数据里可见，不能只是一条横幅。** NAS 断连时：

- 分诊条的「归档失败」从 1 变成 5
- 受影响会议的保留窗口被清零（它们本来就不该开始计时）
- 它们的授权被撤下（没归档成功的东西不该对外可见）
- 告警条上直接给**「暂停到期清理」**——这是唯一能阻止不可逆损失的动作，
  所以它必须在告警条本身上

## 10. 明确不做（YAGNI）

- **AI 问答**（把会议内容送给模型）—— 见 §1.4。留了位置、写了条件，没有实现
- **企微扫码登录控制台** —— 控制台走独立的账号密码体系（D1，2026-08-23）。
  它是 1–3 人的运维面板，价值恰在 NAS 断连、企微不可达这类故障时，**登录不能依赖
  另一个可能同时挂掉的系统**。这不是「以后再说」，是明确不做
- **多租户 / 多企业** —— 单企业部署
- **自助注册 / 找回密码** —— 管理员由系统管理员开通
- **移动端完整体验** —— 移动端只保证「能看」，不保证「能改」，见 §11
